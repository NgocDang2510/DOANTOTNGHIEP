Luồng giao tiếp trong Microservices

Microservices có 2 kiểu giao tiếp: đồng bộ (sync) và bất đồng bộ (async). Dùng đúng kiểu cho đúng tình huống.

Giao tiếp đồng bộ (Synchronous) — dùng khi cần kết quả ngay

Client gọi → đợi → nhận kết quả. Dùng cho: query data, login, hiển thị UI.

Giao tiếp bất đồng bộ (Asynchronous) — dùng khi không cần kết quả ngay

Service publish event → không đợi. Subscriber xử lý khi có thể. Dùng cho: notification, email, cập nhật trạng thái.

// Khi booking được xác nhận — Booking Service KHÔNG gọi trực tiếp các service khác Booking Service ──publish──→ Kafka: "booking.confirmed" { bookingId, roomId, studentId } └──subscribe──→ Payment Service // tạo link thanh toán └──subscribe──→ Notification Service // gửi email/push notification └──subscribe──→ Messaging Service // gửi tin nhắn hệ thống // Khi thanh toán thành công Payment Service ──publish──→ Kafka: "payment.success" └──subscribe──→ Room Service // đổi status → RENTED └──subscribe──→ Notification Service // thông báo sinh viên
💡 Lợi ích của Async (Event-Driven)
Loose coupling
Service không biết nhau tồn tại, chỉ biết event
Resilience
Notification Service chết, Payment vẫn chạy bình thường
Scalability
Thêm subscriber mới mà không sửa publisher
Service Discovery — Services tìm nhau thế nào?
❌ Hardcode (sai)
// Cứng URL — khi scale hoặc đổi IP là vỡ fetch("http://192.168.1.10:8082/api/rooms") fetch("http://localhost:3001/api/messages")
✅ Service Discovery (đúng)
// Dùng tên service — Consul/DNS tự resolve IP fetch("http://room-service/api/rooms") // Consul: "room-service" → 10.0.1.5:8082 // → 10.0.1.6:8082 (nếu scale x2)
SAF dùng Docker DNS — các service gọi nhau qua tên container (http://spring-boot-api:8082, http://nodejs-messaging:3001) — đây là Service Discovery đơn giản, đủ dùng cho scale nhỏ.

SAF so với chuẩn Microservices

Đánh giá thực tế — cái nào đã đạt, cái nào đang thiếu, cái nào không cần thiết cho phạm vi đồ án.

Tiêu chí Chuẩn Microservices SAF hiện tại Mức độ
API Gateway Nginx / Kong / Spring Cloud Gateway Nginx (nginx/api-gateway.conf) — port 80 duy nhất ✅ Đạt
Single Entry Point Chỉ 1 port lộ ra ngoài Port 80 (gateway). Backend internal-only ✅ Đạt
Service Isolation Service không share code, không share DB Tách rõ: Spring Boot / Node.js / AI — DB riêng ✅ Đạt
Polyglot Persistence Mỗi service chọn DB phù hợp MariaDB (nghiệp vụ) + MongoDB (messaging) ✅ Đạt
Service Discovery Consul / Eureka / Kubernetes DNS Docker DNS (tên container) ⚠️ Cơ bản
Health Check Mỗi service có /health, orchestrator tự kiểm tra Có /health + docker-compose healthcheck ✅ Đạt
Independent Deploy Mỗi service có Dockerfile riêng, deploy độc lập Có Dockerfile riêng + docker-compose ✅ Đạt
Auth chia sẻ JWT shared secret hoặc OAuth2 / Identity Server JWT HS512 shared giữa Spring Boot và Node.js ✅ Đạt
Tách nhỏ service Mỗi domain = 1 service (Auth/Room/Booking/Payment riêng) Spring Boot gộp domain; services tách biệt hoàn toàn qua RabbitMQ (không còn HTTP coupling) ⚠️ Tách qua MQ
Message Queue Kafka / RabbitMQ — async event-driven RabbitMQ — Spring Boot publish, Node.js consume → Socket.io push ✅ Đạt
Circuit Breaker Resilience4j — tự fallback khi service lỗi @CircuitBreaker bảo vệ notification publish + VNPay gateway ✅ Đạt
Distributed Tracing Jaeger / Zipkin — theo dõi request qua nhiều service Zipkin (port 9411) + Micrometer — auto-instrument mọi HTTP call ✅ Đạt
Centralized Logging ELK Stack — log tập trung Log riêng từng container (docker logs) ⚠️ Cơ bản
Container Orchestration Kubernetes — auto-scale, self-healing Docker Compose — đủ cho phạm vi đồ án ⚠️ Docker Compose
CI/CD Pipeline GitHub Actions / Jenkins — auto deploy Có GitHub Actions workflow (.github/workflows) ✅ Có
✅ Đã đạt — 11 tiêu chí
API Gateway, Single Entry Point, Service Isolation, Polyglot Persistence, Health Check, Independent Deploy, JWT Auth, CI/CD, Message Queue (RabbitMQ), Circuit Breaker (Resilience4j), Distributed Tracing (Zipkin)
⚠️ Cơ bản — 4 tiêu chí
Service Discovery (Docker DNS thay Consul), Logging (docker logs thay ELK), Spring Boot chưa tách domain riêng, Docker Compose thay vì Kubernetes
❌ Chưa có — 3 tiêu chí
Message Queue (Kafka), Circuit Breaker (Resilience4j), Distributed Tracing (Jaeger)
→ Phù hợp để nói "hướng phát triển tiếp theo" khi báo cáo

12 Nguyên tắc Microservices

Dựa theo "The Twelve-Factor App" + các nguyên tắc Microservices của Martin Fowler. Đây là nền tảng lý thuyết để đánh giá kiến trúc.

#Nguyên tắcÝ nghĩaSAF
1 Single Responsibility Mỗi service chỉ làm 1 việc. "Do one thing and do it well." ⚠️ Node.js/AI đạt, Spring Boot chưa tách
2 Database per Service Mỗi service có DB riêng, không share DB với service khác. ✅ MariaDB (Spring) / MongoDB (Node.js)
3 API Gateway Một điểm vào duy nhất, xử lý auth, routing, rate limit. ✅ Nginx api-gateway
4 Service Discovery Services tự tìm nhau qua registry, không hardcode IP/port. ⚠️ Docker DNS (đơn giản)
5 Loose Coupling Service A không biết implementation của Service B. Chỉ biết API. ✅ Spring Boot → RabbitMQ → Node.js (zero HTTP coupling)
6 High Cohesion Code liên quan đến cùng domain nằm trong cùng service. ✅ Chat code riêng, AI riêng
7 Fault Tolerance Circuit Breaker — lỗi 1 service không lan sang service khác. ✅ Resilience4j @CircuitBreaker trên notification + VNPay
8 Containerization Mỗi service đóng gói trong Docker, chạy độc lập ở bất kỳ đâu. ✅ Dockerfile riêng cho mỗi service
9 Externalized Config Cấu hình qua biến môi trường (.env), không hardcode trong code. ✅ Docker env vars, .env file
10 Observability Logging, Metrics, Tracing — biết hệ thống đang làm gì. ⚠️ /health có, Tracing chưa
11 Independent Deployment Deploy 1 service không ảnh hưởng service khác, không downtime. ✅ Docker Compose service restart riêng
12 Decentralized Data Management Mỗi service quyết định cách lưu data của mình (SQL/NoSQL/Cache). ✅ Polyglot persistence
🚀 Hướng phát triển tiếp theo (nếu được hỏi)
Tách Spring Boot
Chia thành Auth Service + Room Service + Booking Service + Payment Service — mỗi service 1 database riêng
Thêm Kafka
Booking confirmed → event → Payment Service tự động xử lý. Không cần gọi HTTP trực tiếp, giảm coupling
Kubernetes
Tự scale khi traffic tăng, self-healing khi pod crash, rolling deploy không downtime
